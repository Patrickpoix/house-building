# 迁移与复现指南

> 目标：把 `house-building/` 拷到**任何电脑、任何文件夹、任何名字**，都能直接
> 继续开发；也能只取走其中几个 PBR 资产单独使用。

## 1. 为什么可以直接搬

| 机制 | 说明 |
| --- | --- |
| `config.py` 自推导根目录 | 用 `Path(__file__).resolve().parent`，不写死任何路径 |
| 脚本向上查找 `config.py` | 每个脚本开头自动把项目根加入 `sys.path`，层级变化无影响 |
| `.blend` 贴图用 `//` 相对路径 | 相对各自 `.blend` 文件，由 `config.rel()` 统一计算 |
| 无系统级绝对路径 | 全项目 `.py` 中 0 处 `/workspace`、`/root`、`/home` 字面量 |

## 2. 搬整个项目（推荐）

```bash
# 在源机器
zip -r house-building.zip house-building/     # 或直接拷文件夹

# 在目标机器（路径 / 名字随意）
unzip house-building.zip -d ~/MyProjects/
cd ~/MyProjects/house-building                # 也可以改名为 anything

# 自检：确认结构、贴图、144 个资产包、零硬编码
python src/04_tools/migrate_check.py
```

自检输出「全部通过」即可直接按 `03_快速开始.md` 继续开发。

如果自检报贴图断链（例如你在目标机器上又改了内部结构）：

```bash
blpython src/04_tools/relink_all.py           # 批量修复所有 .blend
python src/04_tools/migrate_check.py          # 再验一次
```

### 特殊场景：只把 `config.py` 拆到别处

极少见。此时设环境变量指向项目根：

```bash
export HOUSE_BUILDING_ROOT=/path/to/house-building
```

## 3. 只取用某几个资产

每个资产目录 `assets/by_category/<类别>/<资产ID>/` 是一个独立资产包：

| 文件 | 是否可单独拷走 | 说明 |
| --- | --- | --- |
| `model.blend` | ⚠️ 需带贴图 | ★ 资产本体：完整 4K / 8 通道 PBR，引用 `assets/_textures/` |
| `preview.png` | ✅ 可以 | 预览图，便于快速挑选 |
| `meta.json` | ✅ 可以 | 尺寸、材质、部件数、依赖贴图清单 |

**只拷 `model.blend` 时**：连同 `assets/_textures/<该资产用到的材质>/` 一起拷，
并维持相对层级；或在新位置跑一次 `relink_textures.py` 重定位。
`meta.json` 的 `textures` 字段列出了该资产依赖的全部贴图相对路径，按它拷贝即可。
最省事的是把整个 `house-building/` 拷走——保持结构即无需任何修复。

### 可选：导出 GLB 给别的软件

默认工程不含 GLB（避免与 `model.blend` 几何重复、内嵌缩略贴图）。需要把资产
交给 Unity / Unreal / three.js / 网页查看器时，按需导出自包含 GLB：

```bash
blpython src/04_tools/export_glb.py -- AST_01_001_餐椅_A     # 单个资产
blpython src/04_tools/export_glb.py -- 01 03 07              # 按类别号
blpython src/04_tools/export_glb.py -- all                   # 144 个全量
```

产物为各资产目录的 `model.glb`（内嵌 1K 贴图，单文件 2–4 MB，完全自包含），
用完可删；`model.blend` 不会被改写，始终保持完整 4K 引用。

## 4. 在新环境复现全部产物

```bash
python3.11 -m venv .venv && . .venv/bin/activate
pip install bpy==4.5.15 numpy pillow
# 然后按 docs/03_快速开始.md 的 ①→⑦ 顺序执行
```

产物全部由脚本生成，理论上可从 `src/` + `reference/` + `config.py` 完整重建。
`assets/`、`scene/`、`renders/` 是当前已跑出的结果，可直接用，也可重跑覆盖。

## 5. 声明式布局与组装产物跟着一起搬

`scene/layouts/*.json` 是纯文本、零路径依赖，整包搬到任何位置都能用；
`scene/assembled/` 里的房屋 `.blend` 内嵌了所用资产几何、4K 贴图走 `//`
相对路径，只要连同 `assets/_textures/` 一起搬就正常打开。二者都是**可再生的**：
删掉整个 `assembled/` 后在新位置重跑
`blpython src/02_scene/assemble.py -- --all --render` 即可完全重建。
详见 `docs/09_任意组装指南.md`。

## 6. 迁移后不要做的事

- ❌ 不要手动把 `.blend` 里贴图路径改成绝对路径（会破坏可迁移性）。
- ❌ 不要在各脚本里另写一份路径常量（唯一来源是 `config.py`）。
- ❌ 不要删 `config.py` 或改变 `MATERIALS` / `CHANNELS` 而不改贴图文件名，
  `tex_by_name()` 依赖 `<材质>_<通道>.png` 的命名解析。
- ❌ 不要把 `by_category/` 下的资产目录改名后不更新 `catalog.csv`，
  自检会以 `catalog.csv` 为准核对 144 个资产。

## 7. 校验清单

搬完后 `migrate_check.py` 会依次检查：

1. 目录树完整
2. 128 张 4K 贴图齐全且 basecolor 为 4096²
3. 36 个类别目录 / 144 个资产目录 / 每个三件套齐全
4. 源码零硬编码绝对路径
5. 母库、房屋、抽样独立资产的 `.blend` 贴图相对且可解析
6. README、目录规范、迁移 / 组装指南、场景文件齐备
7. `scene/layouts/` 下布局 JSON 齐全、引用的资产 ID 合法
