# house-building · 目录规范

> 这份文档是给**接手这个项目的人或 AI agent**看的。读完它，你应该能立刻知道
> 文件在哪、改哪里、怎么加新资产，而不会把结构重新弄乱。

## 0. 三条铁律

1. **路径只有一个来源**：`config.py`。任何脚本都不许写死绝对路径，一律
   `import config as C`，用 `C.XXX` 取路径。新增路径请在 `config.py` 里加，
   不要在各脚本里各写一份。
2. **整个文件夹可搬迁**：`house-building/` 可以改名、拷到任何磁盘 / 系统，
   `config.py` 用自身位置推导根目录，所有 `.blend` 内贴图用 `//` 相对路径。
   搬完跑一次 `python src/04_tools/migrate_check.py` 自检。
3. **源码与产出分离**：`src/` 只放代码，`assets/` / `scene/` / `renders/` 放产出。
   产出可以由脚本重建，不要在产出里手改内容后以为会被保留。

## 2. 命名约定

| 对象 | 格式 | 示例 |
| --- | --- | --- |
| 资产 ID | `AST_<类别号>_<序号>_<中文名>_<变体>` | `AST_03_001_沙发_A` |
| 类别目录 | `<类别号>_<英文名>_<中文名>` | `03_Sofas_沙发` |
| 贴图文件 | `<材质>_<通道>.png` | `oak_wood_normal.png` |
| 材质目录 | `<材质名>` | `_textures/oak_wood/` |
| 独立资产文件 | 固定三件套 | `model.blend` / `preview.png` / `meta.json` |
| 脚本 | 动词开头，按阶段放对应子目录 | `build_library.py` |

**贴图文件名全局唯一**（`<材质>_<通道>`），这是 `config.tex_by_name()` 能按
文件名重定位路径的前提。改文件名必须同步更新 `config.py` 的 `MATERIALS` / `CHANNELS`。

## 3. 常见维护动作

| 想做的事 | 改哪里 / 跑什么 |
| --- | --- |
| 新增一种材质 | `config.py` 的 `MATERIALS` → `src/00_textures/make_ai_textures.py` 的 `SPEC` → 重跑贴图 → 重跑资产库 |
| 新增一个资产 | `src/01_assets/build_library.py` 的 `CATEGORIES` / builder → 重跑 `build_library.py` → 重跑 `export_assets.py` |
| 改目录结构 | **只改 `config.py`**，然后 `python src/04_tools/relink_all.py` 修贴图路径 |
| 搬家 / 换电脑 | 整个文件夹拷走 → `python src/04_tools/migrate_check.py` |
| 全部重建 | 按 `docs/03_快速开始.md` 的流水线顺序跑一遍 |
| 检查现状 | `blpython src/04_tools/verify.py`（需 bpy） |
| 拼一栋不同的房屋 | 复制 `scene/layouts/*.json` 改尺寸 / 隔墙 / 资产 → `blpython src/02_scene/assemble.py -- <布局>.json --render`（见 `docs/09`） |

## 4. 为什么这样分层

- **资产按类别与 ID 落成真实目录**：`by_category/` 下 36 类、每类 4 个资产
  都是独立目录，能直接数出 144 个、单独取用；母库 `asset_library.blend`
  只作为场景实例引用源保留在 `_library/`。
- **贴图按材质分目录**：128 张 4K PNG 平铺时无法分辨归属，现在每种材质一个目录。
- **脚本按流水线阶段分目录**：新接手的人看目录名就知道先跑哪个、后跑哪个。
- **布局与组装产物分离**：`layouts/` 是纯文本配置（人改的），`assembled/` 是脚本
  生成的成品（可整目录删除重建）。二者不混放，改配置不会被产物覆盖。
- **`renders/` 按用途分目录**：主图 / 特写 / 4K / 检视不再混在一起。
- **只保留一套当前产物**：同一份资产只存一份几何 + 一套 4K PBR，不再同时存
  内嵌 1K 缩略贴图的 glTF 副本；也不保留历史基线与版本对比目录，避免「不知道
  哪份是最新的」。需要跨软件单文件复用时用 `src/04_tools/export_glb.py` 按需导出，
  需要双图对比时用 `src/04_tools/compare.py` 并自行指定输出路径。
